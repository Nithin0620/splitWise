# SplitWise

Full-stack shared-expense tracker. Create trips, add expenses with flexible splits, see who owes whom, settle up, invite friends by email, and get live updates on web and mobile.

This repository is a monorepo with three independent packages (there is **no** root `package.json`; install and run each package separately):

| Package   | What it is |
| --------- | ---------- |
| `backend` | Express 4 + MongoDB REST API. Google OAuth, JWT auth, Ably realtime, email invites, notifications, recurring expenses, multi-currency. Ships as a Node server (Docker) or a Cloudflare Worker. |
| `web`     | React 19 + Vite + Tailwind CSS v4 single-page app. |
| `mobile`  | Expo SDK 58 / React Native 0.88 app using Expo Router. Android, iOS, and web targets. |

`Design.md` contains the product/design notes. `mobile/AGENTS.md` contains Expo-specific guidance for coding agents.

## Prerequisites

- **Node.js 22 LTS** (the backend Docker image uses `node:22-alpine`; Vite 8 and Expo 58 require a modern Node release).
- **npm** (each package has a `package-lock.json`; use `npm ci` in CI).
- **MongoDB 7+** locally, in Docker, or MongoDB Atlas.
- **Android builds:** JDK 17, Android SDK (platform 36 + build-tools), `ANDROID_HOME` set. Optional: an emulator or a USB-debugging-enabled phone with `adb`.
- **Accounts/keys for optional features:** Google OAuth credentials, Resend (invite email), Ably (realtime), Cloudflare (Workers/Pages deployment), Expo/EAS (cloud mobile builds).

Set Android tooling on Linux/macOS as needed:

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
java -version   # must report 17.x
```

## Quick start (local development)

### 1. Backend API

```bash
cd backend
npm install
cp .env.example .env
# edit .env (at minimum MONGO_URI, JWT_SECRET, GOOGLE_* and ABLY_API_KEY)
npm run dev          # nodemon, http://localhost:5000
```

You need MongoDB. Either use Atlas or start one with Docker:

```bash
docker run -d --name splitwise-mongo -p 27017:27017 mongo:7
```

Generate a strong JWT secret:

```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

Health check: `curl http://localhost:5000/api/health`.

### 2. Web app

```bash
cd web
npm install
cp .env.example .env
npm run dev          # http://localhost:5173
```

With `VITE_API_URL` empty, Vite proxies `/api` and `/socket.io` to `http://localhost:5000` (see `web/vite.config.js`), so local development works without CORS setup. To point at a deployed API, set `VITE_API_URL` to the backend **origin** (no `/api` suffix, no trailing slash).

The public landing page is served at `/`; the authenticated app lives at `/dashboard`. The landing page includes the Android APK install button (Google Drive link).

### 3. Mobile app

```bash
cd mobile
npm install
# create mobile/.env (gitignored) with the API base URL:
#   physical device on the same Wi-Fi: http://<your-lan-ip>:5000/api
#   Android emulator:                  http://10.0.2.2:5000/api
#   production:                        https://your-api.example.com/api
npx expo start
```

`EXPO_PUBLIC_*` values are inlined at bundle/build time. If `mobile/.env` is missing, the app falls back to the production API URL defined in `mobile/src/lib/api.js`.

OAuth, SecureStore, and some native modules require a **development build**, not Expo Go:

```bash
cd mobile
npx expo run:android   # builds + installs a debug dev build
npx expo start         # start Metro afterwards
```

When using a physical device over USB you can forward Metro instead of using the LAN URL:

```bash
adb reverse tcp:8081 tcp:8081
```

Never edit `mobile/android/` or `mobile/ios/` by hand. They are generated by Expo prebuild (Continuous Native Generation) and gitignored. Configure native behavior in `mobile/app.json` and Expo config plugins.

### Run everything together

Use three terminals: backend on `:5000`, web on `:5173`, and Expo/Metro for mobile. Log in with the same Google account on all three; the backend issues a JWT and each client stores it (`localStorage` on web, Expo SecureStore on mobile).

## Environment variables

All `.env` files are gitignored. Never commit secrets. Only commit `.env.example` files.

### `backend/.env`

| Variable | Required | Description |
| -------- | -------- | ----------- |
| `PORT` | No | HTTP port for the Node server. Default `5000`; the Docker image sets `8000`. |
| `NODE_ENV` | No | `development` or `production`. Affects cookies (`secure` in production). |
| `MONGO_URI` | Yes | MongoDB connection string. Use `mongodb://` (not `mongodb+srv://`) on Cloudflare Workers. |
| `JWT_SECRET` | Yes | Long random string used to sign JWTs. |
| `JWT_EXPIRES_IN` | No | Token lifetime, default `7d`. |
| `GOOGLE_CLIENT_ID` | For OAuth | Google OAuth client ID. |
| `GOOGLE_CLIENT_SECRET` | For OAuth | Google OAuth client secret. |
| `GOOGLE_CALLBACK_URL` | For OAuth | Must exactly match the Authorised redirect URI in Google Cloud Console, e.g. `https://api.example.com/api/auth/google/callback`. |
| `CLIENT_URL` | Yes | Web origin used for CORS and the OAuth web fallback. Comma-separate multiple origins. |
| `RESEND_API_KEY` | For invites | Resend API key used to send invitation emails. |
| `RESEND_FROM_EMAIL` | For invites | Verified sender, e.g. `SplitWise <onboarding@resend.dev>` for the sandbox. |
| `INVITE_BASE_URL` | No | Base URL embedded in invite emails. Defaults to `CLIENT_URL`. |
| `ABLY_API_KEY` | For realtime | Ably key used by `/api/realtime/token`. Realtime endpoints return 503 without it. |
| `CF_WORKER` | Auto | Set to `1` by `backend/worker.js`; do not set manually. |

### `web/.env` (build-time)

| Variable | Description |
| -------- | ----------- |
| `VITE_API_URL` | Backend **origin**, e.g. `https://api.example.com`. Leave empty in development to use the Vite proxy. |
| `VITE_SOCKET_URL` | Legacy Socket.IO setting. The current realtime client uses Ably; this value is unused. |

Because Vite inlines `VITE_*` variables at build time, set `VITE_API_URL` for the build command that produces the deployed bundle.

### `mobile/.env` (build-time)

| Variable | Description |
| -------- | ----------- |
| `EXPO_PUBLIC_API_URL` | Full API base including `/api`, e.g. `https://api.example.com/api`. Defaults to the value in `mobile/src/lib/api.js`. |

For release builds, create/update `mobile/.env` **before** running Gradle or EAS so the URL is embedded in the bundle.

## Authentication and OAuth

- Login is Google OAuth only. The backend issues a JWT (`{ id: userId }`) valid for `JWT_EXPIRES_IN` (default 7 days).
- The API accepts the token as `Authorization: Bearer <token>` or as the `token` HTTP-only cookie.
- Web stores the token in `localStorage` (`sw_token`). Mobile stores it in Expo SecureStore (`sw_token`).
- The API is protected per route; trip-level access is enforced by `backend/middleware/tripAccess.js`.

### Web flow

1. The browser visits `<API>/api/auth/google`.
2. Google redirects back to `GOOGLE_CALLBACK_URL`.
3. The backend redirects to `<CLIENT_URL>/auth/callback?token=<jwt>`.
4. `web/src/pages/AuthCallback.jsx` stores the token and sends the user into the app.

Set the Google Console **Authorised redirect URI** to exactly `GOOGLE_CALLBACK_URL`, and set backend `CLIENT_URL` to the web origin (comma-separate additional origins).

### Mobile flow

1. `mobile/app/(auth)/login.jsx` builds a redirect with `makeRedirectUri({ scheme: 'splitwise', path: 'auth/callback' })` (Expo Go uses `exp://...`).
2. It opens `<API>/api/auth/google?redirectUri=<encoded redirect>` in a browser session.
3. The backend validates the redirect protocol and carries it through Google's `state` parameter (base64url).
4. The callback decodes `state`, appends `?token=<jwt>`, and redirects back into the app via the custom scheme.
5. The app stores the token in SecureStore.

Allowed redirect protocols are `splitwise:`, `exp:`, `exps:`, and `exp+splitwise:` (see `backend/routes/auth.js`). The Android intent filter lives in `mobile/app.json` with `autoVerify: false` (custom scheme, not HTTPS App Links). Custom-scheme OAuth requires a development/standalone build; Expo Go only handles `exp://` redirects.

## Realtime updates

Realtime is powered by **Ably**, which works on both long-running Node servers and Cloudflare Workers.

- The backend publishes to `trip:<tripId>` and `user:<userId>` channels (`backend/config/ably.js`).
- Clients authenticate to Ably through `GET /api/realtime/token`, which returns a scoped token request for the user (subscribe-only on their trips and user channel).
- Web (`web/src/lib/socket.js`) and mobile (`mobile/src/lib/socket.js`) share the same event names (`expense_created`, `settlement_created`, `member_added`, `trip_updated`, etc.).
- If `ABLY_API_KEY` is not set, live updates are disabled but the REST API still works.

Socket.IO exists only as legacy code in `backend/config/socket.js` and is not used by the current web/mobile clients. It cannot run on Cloudflare Workers.

## API overview

Base URL: `<origin>/api`

| Route | Purpose |
| ----- | ------- |
| `GET /health` | Liveness/DB status (no DB connection required). |
| `/auth` | Google OAuth start/callback, `GET /me`, `POST /logout`. |
| `/trips` | Create/list/read/update/archive trips and members. |
| `/expenses` | CRUD, split types, items/tax/tip, recurrence. |
| `/settlements` | Record and delete payments between members. |
| `/invites` | Create/list invites, public preview, accept by token. |
| `/notifications` | List, mark read/all read. |
| `/currencies` | Supported currencies and exchange rates. |
| `/realtime/token` | Ably token request (authenticated). |

Balance math lives in `backend/utils/balanceCalculator.js` and is unit-tested.

## Production deployment

### Backend on Docker, Cloud Run, Koyeb, Render, or Fly

The `backend/Dockerfile` builds a production image that listens on `PORT` (default `8000`), runs as a non-root user, and health-checks `/api/health`.

```bash
cd backend
docker build -t splitwise-api .
docker run --env-file .env -p 8000:8000 splitwise-api
```

Cloud Run example (adjust region and secrets):

```bash
gcloud run deploy splitwise-api \
  --source backend \
  --region asia-south1 \
  --allow-unauthenticated \
  --port 8000 \
  --set-env-vars NODE_ENV=production,CLIENT_URL=https://app.example.com \
  --set-secrets MONGO_URI=mongo-uri:latest,JWT_SECRET=jwt-secret:latest,ABLY_API_KEY=ably-key:latest
```

Any platform that can run a container works. Requirements:

- Set every variable from the backend table above.
- `CLIENT_URL` must include the deployed web origin for CORS and OAuth fallback.
- `GOOGLE_CALLBACK_URL` must use the deployed API domain and match Google Console.
- The recurring-expense scheduler runs hourly inside the Node server (`backend/utils/recurring.js`). Serverless platforms that freeze idle instances will not run it reliably.

### Backend on Cloudflare Workers

`backend/worker.js` mounts the Express app through `cloudflare:node`, and `wrangler.jsonc` selects it.

```bash
cd backend
npx wrangler login
npx wrangler secret put MONGO_URI
npx wrangler secret put JWT_SECRET
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
npx wrangler secret put GOOGLE_CALLBACK_URL
npx wrangler secret put CLIENT_URL
npx wrangler secret put ABLY_API_KEY
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put RESEND_FROM_EMAIL
npx wrangler secret put INVITE_BASE_URL
npm run deploy
```

Worker limitations:

- Use a standard `mongodb://` connection string; `mongodb+srv://` is not supported in the Workers runtime.
- Socket.IO is unavailable; realtime uses Ably only.
- The hourly recurring scheduler does not run. Trigger `runDueRecurringExpenses()` from a cron if needed.
- Request bodies are limited to 1 MB.

### Web on Cloudflare Pages (or any static host)

```bash
cd web
npm ci
VITE_API_URL=https://api.example.com npm run build
npx wrangler pages deploy dist --project-name <pages-project>
```

The output is a static SPA in `web/dist`. The host must:

- Serve `index.html` for unknown routes (SPA fallback), so `/auth/callback`, `/invite/accept`, and `/login` deep links work. On Cloudflare Pages add a `web/public/_redirects` file containing `/* /index.html 200`, or configure SPA fallback in the Pages dashboard. Netlify uses the same `_redirects` syntax; Nginx needs `try_files $uri /index.html;`.
- Set the backend `CLIENT_URL` to the deployed web origin.
- Rebuild whenever `VITE_API_URL` changes (it is embedded at build time).

`web/public/sw.js` is a small service worker for offline navigation. Bump its `CACHE` version when you need to invalidate old cached assets.

## Build an installable Android APK

### Fastest: local release APK

Prerequisites: JDK 17, Android SDK, `ANDROID_HOME` exported, and `mobile/android/` generated.

```bash
cd mobile

# First time only, or after changing app.json / native config:
npx expo prebuild --platform android

cd android
./gradlew assembleRelease
```

Output:

```
mobile/android/app/build/outputs/apk/release/app-release.apk
```

Install it on a connected phone:

```bash
adb install -r mobile/android/app/build/outputs/apk/release/app-release.apk
```

Or build and install in one step (device must be connected):

```bash
cd mobile
npx expo run:android --variant release
```

Notes:

- The first release build takes roughly 5-15 minutes; later builds are incremental.
- The universal APK contains all ABIs and is around 90 MB.
- Set `mobile/.env` (`EXPO_PUBLIC_API_URL`) **before** building so the APK points at the intended API. With no `.env`, it uses the production default in `mobile/src/lib/api.js`.

### Smaller APK for a single phone architecture

Most modern phones are `arm64-v8a`. You can build only that native ABI:

```bash
cd mobile/android
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
```

Or set `reactNativeArchitectures=arm64-v8a` in `android/gradle.properties` (this file is regenerated by prebuild, so the property override is often easier).

### Cloud build with EAS (recommended for Play Store / stable signing)

`mobile/eas.json` defines three profiles. `preview` uses internal distribution and produces an APK; `production` produces an AAB for Google Play and auto-increments versions.

```bash
cd mobile
npx eas-cli@latest login
npx eas-cli@latest build -p android --profile preview      # installable APK
npx eas-cli@latest build -p android --profile production   # AAB for Play Store
npx eas-cli@latest submit -p android                       # upload the AAB
```

EAS manages the Android keystore for you. Keep the credentials EAS generates; losing them prevents updates to an app already installed from the Play Store.

### Signing, versioning, and updates

- The Gradle project generated by Expo signs `release` with `signingConfigs.debug` (`android/app/debug.keystore`, password `android`). That APK is fine for sideloading but **not** for Google Play.
- `mobile/android/` and `mobile/ios/` are generated and gitignored. `npx expo prebuild --clean` deletes them and creates a **new** debug keystore. An APK signed with a different key cannot update an installed app: uninstall first (`adb uninstall com.splitwise.app`) or restore the original `debug.keystore` before building.
- For a stable local release key, generate your own keystore and wire it into `android/app/build.gradle` (`signingConfigs.release`) or `~/.gradle/gradle.properties`. Because `android/` is regenerated, repeat this after `--clean`; EAS avoids that problem entirely.
- Bump `expo.version` in `mobile/app.json`, and add `android.versionCode` (and `ios.buildNumber`) when you need a new store version. Re-run prebuild after changing `app.json`. The EAS `production` profile auto-increments.
- Keep a backup of any keystore you use. Losing it means you can never update the installed app under the same package name.

## Troubleshooting

| Symptom | Fix |
| ------- | --- |
| `app-release.apk` installs but Android says "App not installed" | Signature mismatch. Uninstall the old app: `adb uninstall com.splitwise.app`, then install again. This happens after `expo prebuild --clean` regenerates the debug keystore. |
| Gradle build fails with "SDK location not found" | Export `ANDROID_HOME` and make sure `mobile/android/local.properties` points at the SDK (`sdk.dir=...`). Re-run `npx expo prebuild --platform android`. |
| Gradle build fails with an unsupported Java version | Use JDK 17 (`java -version`). |
| `redirect_uri_mismatch` from Google | `GOOGLE_CALLBACK_URL` must exactly match the Authorised redirect URI in Google Cloud Console. |
| OAuth returns to the web app instead of the mobile app | The `state` redirect was missing/rejected. Use a development/standalone build (not Expo Go), confirm the `splitwise` scheme is registered, and use an allowed protocol. |
| Web requests blocked by CORS | Add the web origin to `CLIENT_URL` on the backend (comma-separated list). |
| Web deep links 404 after deploy | Configure SPA fallback to `index.html` on the static host. |
| Realtime does not work | Set `ABLY_API_KEY`; `GET /api/realtime/token` returns 503 without it. |
| Mobile cannot reach the backend | Use the LAN IP for a physical device (not `localhost`), `10.0.2.2` for the Android emulator, and keep the backend bound to `0.0.0.0`. Release Android builds block cleartext HTTP, so use HTTPS for production. |
| Expo Go cannot complete login or use a native module | Build a development client: `npx expo run:android` or `eas build --profile development`. |
| Changes to `app.json` have no effect natively | Re-run `npx expo prebuild --platform android` and rebuild. |
| Metro cannot connect over USB | Run `adb reverse tcp:8081 tcp:8081`, then reload the app. |

## Project conventions

- Backend is CommonJS (`"type": "commonjs"`); web is ESM; mobile uses Expo Router file-based routes under `mobile/app`.
- Keep non-route mobile code outside `mobile/app` (components/context/lib/theme live in `mobile/src`).
- Use `npx expo install` for Expo/React Native dependencies so versions stay SDK-compatible.
- Never commit `.env` files, keystores, or generated `android/`/`ios/` directories.
- Use `backend/.env.example` and `web/.env.example` as the source of truth for configuration.
